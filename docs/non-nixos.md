# Without NixOS

NixOS is the only tested route. This page shows how the NixOS build uses
the kernel and power-profiles-daemon patches, so you can reproduce that by
hand. There is no tested DKMS package, distribution package or installer,
and none is planned in this project.

## Kernel driver

- Base file: `kernel/acer-wmi/base/acer-wmi.c`, Linux
  platform-drivers-x86 `review-ilpo-next` at
  `2622c23b7b640476a06d767b6ae63315ba5993a8` (provenance and hash in
  `kernel/acer-wmi/BASE`).
- Patches: `kernel/acer-wmi/patches/0001-*.patch` to `0011-*.patch`,
  applied in file-name order. Apply them with `git am` to a
  platform-drivers-x86 tree at the base commit, or apply only their
  `acer-wmi.c` hunks to the base file. Patch 0009 changes only Kconfig and
  has no such hunk. Check the patched file against the head hash in
  `kernel/acer-wmi/SOURCE` before building; `patch` may otherwise apply
  hunks with fuzz to a different base.
- Out-of-tree build, as `pkgs/acer-wmi-pt516/default.nix` does it
  (`filterdiff` is in patchutils):

  ```sh
  cp kernel/acer-wmi/base/acer-wmi.c .
  for p in kernel/acer-wmi/patches/*.patch; do
    filterdiff --include='*/drivers/platform/x86/acer-wmi.c' "$p" > m.patch
    [ -s m.patch ] && patch -p1 acer-wmi.c < m.patch
  done
  sha256sum acer-wmi.c   # must equal "acer-wmi.c at head" in kernel/acer-wmi/SOURCE
  mv acer-wmi.c acer-wmi-pt516.c
  echo 'obj-m := acer-wmi-pt516.o' > Makefile
  make -C /lib/modules/$(uname -r)/build M=$PWD modules
  ```

- Install with `make -C /lib/modules/$(uname -r)/build M=$PWD
  modules_install` and `depmod -a`. Then add a file under `/etc/modprobe.d/`
  with `blacklist acer_wmi` and, for the Windows-style on/off Turbo key,
  `options acer_wmi_pt516 cycle_gaming_thermal_profile=0`. Without that
  option the key cycles the platform profiles, which is the driver's
  default. Both modules carry the same WMI alias, so with the stock module
  blacklisted udev loads `acer_wmi_pt516`. Rebuild after every kernel
  update.
- The running kernel must build the stock driver as a module
  (`CONFIG_ACER_WMI=m`, which brings `CONFIG_ACPI_PLATFORM_PROFILE` and the
  driver's other dependencies; a built-in `acer_wmi` cannot be blacklisted)
  and must enable `CONFIG_LEDS_CLASS_MULTICOLOR`, which patch 0009 makes a
  dependency. I run it on 7.2.7; it also compiles against 6.18.52, which I have not
  booted. Other kernels are untested.

## power-profiles-daemon

`patches/power-profiles-daemon/0001-*.patch` (the `balanced-performance`
spelling) and `0002-*.patch` (the powersave governor before EPP) apply to
the 0.30 release with `patch -p1` in the source tree. Other versions are
not verified.

## thermald

thermald must run with `--adaptive` so it applies the firmware's DTT
tables, with `Restart=on-failure` and `SuccessExitStatus=2` in its unit;
upstream thermald's unit already has both settings, and the hardware
module adds them only because the NixOS unit lacks them.

## Broker and session policy

`pkgs/turbo-broker/turbo-broker.py` and `pkgs/turbo-agent/agent.py` are
plain Python 3 (the agent needs `dbus-next`), but their units, groups,
polkit rule and configuration files are generated by the NixOS modules.
Reproducing them elsewhere means reading `modules/broker/default.nix` and
`modules/policy/default.nix`; this is untested.
